Essential Git Commands

Categorized workflow guide for new projects, pulling updates, commit messages, and daily usage.

1. New Project Setup
git initStep 1

Initialize a brand-new empty Git repository in your local project folder.

git branch -M mainStep 2

Rename the default branch to main (standard naming convention for modern remote hosts).

git remote add origin <url>Step 3

Link your local repository to a new remote server URL (GitHub, GitLab, Bitbucket).

git push -u origin mainStep 4

Push local commits to the remote repository and set upstream tracking for future pushes.

2. Pull Updates Workflow
git statusStep 1

Check working tree status to inspect current local modifications and untracked files before pulling updates.

git stashStep 2

Temporarily shelter uncommitted local changes into a clean working stack to avoid conflicts during pull.

git branchStep 3

List all local branches and highlight the active branch you are currently working on.

git checkout <branch_name>Step 4

Switch your local working directory to the specified target branch (e.g., git checkout main).

git pull origin mainStep 5

Fetch and merge the latest remote commits directly from the main branch on GitHub.

git stash popStep 6

Re-apply your previously stashed local changes back onto the newly updated codebase and remove them from the stash stack.

3. Branching Workflow
git branch <branch-name>Create

Creates a new branch locally without switching to it (you remain on your current branch).

git checkout <branch-name>Switch

Switches your working directory to an existing local branch that you created previously.

git checkout -b <branch-name>Create & Switch

Creates a brand-new branch and immediately switches to it in a single combined step.

4. Conventional Commit Types
Format: type(scope): short description
Example: feat(student-courses): add countdown pill
Use the imperative mood and keep it under 72 characters. The (scope) is optional.
TypePurpose / UsageExample Commit Message
feat

Adding a new feature or UI component to the codebase.

git commit -m "feat: add user profile page"
fix

Fixing a bug, error, or unexpected UI/logic issue.

git commit -m "fix: resolve navigation dropdown glitch"
refactor

Restructuring existing code without changing its external behavior.

git commit -m "refactor: optimize auth state management"
style

Code formatting only (spaces, semicolons, Prettier) with no logic change.

git commit -m "style: format button component with prettier"
docs

Updating documentation, README.md, or code comments.

git commit -m "docs: update API setup guidelines"
chore

Maintenance tasks, updating dependencies, or modifying config files.

git commit -m "chore: update tailwind packages"
perf

Performance improvements that speed up rendering or execution.

git commit -m "perf: lazy load heavy assets"
test

Adding or updating unit or integration tests.

git commit -m "test: add unit test for login form"
build

Changes to the build system or major dependencies.

git commit -m "build: upgrade next to 15"
ci

Changes to CI/CD pipeline files.

git commit -m "ci: add lint step to pipeline"
revert

Reverting a previous commit.

git commit -m "revert: revert add countdown pill"
5. Commit Types Explained
featNew

Adds something new that the user or the system did not have before.

  • Use when: adding a page, button, endpoint, or database field.
  • Not when: you are fixing something that already exists but is broken.
feat(api): add course-pills endpoint
fixBug

Corrects something that was broken or returned a wrong result.

  • Use when: resolving an error, a wrong calculation, or a broken layout.
  • Not when: you are adding new behavior (use feat).
fix(api): return empty list when no enrollments
refactorInternal

Reorganizes code internally. The behavior the user sees stays exactly the same.

  • Use when: splitting a large function, moving files, renaming, or removing duplication.
  • Not when: the result changes in any way.
refactor(hooks): extract useCountdown
styleFormat

Code formatting only, with no change to logic or behavior.

  • Use when: running Prettier or ESLint, fixing spaces, semicolons, or import order.
  • Not when: you are changing how the UI looks. Use feat for a new design or fix for a broken one.
style: format course card with prettier
testTests

Adds or updates tests without touching application code.

  • Use when: the commit contains only unit, integration, or e2e test files.
  • Not when: you also changed app code. Split it into two commits.
test: add countdown hook unit tests
choreMaintenance

Housekeeping around the project that users never notice.

  • Use when: editing config files, .gitignore, scripts, seed data, or removing dead files.
  • Not when: it changes app behavior, or fits a more specific type.
chore(db): update seed data
docsDocs

Changes to documentation only.

  • Use when: editing the README, guides, or code comments.
  • Not when: you changed code together with the docs.
docs: update setup instructions
perfSpeed

Makes something faster or lighter without changing what it does.

  • Use when: fixing N+1 queries, slow renders, or heavy assets.
  • Not when: the change is only cleanup (use refactor).
perf(api): fix N+1 query in pills
buildBuild

Changes to the build system or major dependencies.

  • Use when: upgrading a framework version or changing bundler config.
  • Not when: it is a small routine bump (chore(deps) is fine).
build: upgrade next to 15
ciPipeline

Changes to CI/CD pipeline files.

  • Use when: editing GitHub Actions or other automation workflows.
  • Not when: you are changing app code.
ci: add lint step to pipeline
revertUndo

Records the reversal of an earlier commit in history.

  • Use when: a previous commit must be undone safely (pairs with git revert).
  • Not when: you just want to amend your own unpushed commit.
revert: revert "feat: add countdown pill"
Breaking change? Add ! after the type: feat(api)!: change course-pills response shape
6. Most Frequently Used
git statusHigh Usage

Check the status of modified, staged, or untracked files in your working directory.

git add -AHigh Usage

Stage all changes (new, modified, and deleted files) across the entire project repository.

git commit -m "msg"High Usage

Record staged changes into the repository history with a descriptive commit message.

git log --onelineHigh Usage

View a concise, single-line commit history log with short hashes and commit messages.

git add <file-name>High Usage

Stage a specific individual file to prepare it for the next commit.

.gitignoreEssential File

Specify intentionally untracked files and folders (e.g., node_modules/, .env) to ignore.

7. Secondary & Utility Commands
git status -s

Display short-format working tree status using two-character status indicators.

git add *

Stage all modified and new files in the current working folder.

git add *.ext

Stage files matching a specific pattern or extension (e.g., git add *.js).

.git/info/exclude

Define local-only ignore rules specific to your machine without sharing them with the team.

git log

Show full commit history, including author, date, and full commit messages.

git revert <hash>

Safely undo changes from a past commit by creating a new inverse commit.

git reset <hash>

Reset HEAD state to a specified commit using flags (--soft, --hard).
